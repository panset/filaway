# Filaway — Phase 1 Implementation Plan

## Context

Filaway is a macOS notes app (spec v0.3, `~/Downloads/functional-spec.html`) where an AI files notes after each writing session and retrieval is natural-language. This repo is empty; this document is the ordered, buildable plan for Phase 1 (M1–M4), to be executed by Opus sub-agents with the user (solo dev, first Mac app) reviewing. Requirement IDs refer to the spec. Stack decision confirmed with the user: **native Swift, no Go/Bazel in Phase 1.**

Legend: sizes in hours (S ≤4, M 5–10, L 11–16, XL >16). `[ASSUMPTION]` = spec doesn't settle it. `⚠ AMEND` = spec conflict / technically unwise; amendment proposed, not silently deviated.

## 1. Tech decisions

| Area | Decision | Rationale (one line) |
|---|---|---|
| Language / UI | Swift 6 toolchain (Xcode 16.4+), SwiftUI shell + AppKit where SwiftUI is weak (editor, toolbar search field). Min macOS 14, universal (arm64+x86_64). | Only stack that meets NFR-7/NFR-6 natively and gets Keychain, FSEvents, Core ML, Sparkle, notarization for free. **Contentious:** user preferred Go+Bazel; no Go macOS UI is native, Bazel Apple rules fight Xcode signing tooling. Decided with user: Swift. |
| Build system | SwiftPM package `FilawayCore` (all logic, CLI-testable with `swift test`) + thin app target generated by **XcodeGen** from `project.yml` (`.xcodeproj` gitignored) + `Makefile` (`build/test/bench/app/dmg/notarize/release`). | Text-only project definition = clean diffs and agent-friendly; core is testable without Xcode GUI. Bazel revisit only if a shared cross-platform core appears in Phase 3. |
| Editor | `NSTextView` (TextKit 2) wrapped in `NSViewRepresentable`, **styled Markdown source** ("WYSIWYM"): the text storage *is* the file bytes; a custom `NSTextStorage` applies attributes (headings, bold/italic, list/checkbox glyphs, dimmed syntax marks); fenced code = custom layout fragment background + hover overlay `Copy` button. | Zero serialization loss → DS-1 trivially true, external edits reconcile as plain text, no Markdown round-trip bugs. **Contentious:** WYSIWYG rich-text-over-Markdown looks nicer but is lossy and 3× the work; web editor (CodeMirror in WKWebView) breaks native feel/a11y. |
| Markdown parsing | Apple `swift-markdown` for structure (chunking, code-block extraction, diffs); a small line-based incremental highlighter (own, ~300 LOC) for per-keystroke editor styling. | cmark is correct but not incremental; keystroke path needs to be O(changed lines). |
| Storage layout | `<root>/<Folder>/<Sub>/<Title>.md`; filename stem = title; Library depth ≤ 2; nothing but `.md` files and folders in the user's tree. Default root `~/Notes`; stored as a bookmark (NFR-5, may be external volume). | DS-1 literal; Finder-readable; Phase 2 sync = point at folder. |
| Metadata (DS-2) | **Hybrid:** minimal YAML front-matter (`id`, `created`, `tags`) written only when *the app* saves a note; edited time = file mtime; AI provenance, last-opened, baselines → SQLite in App Support. Tolerant parser: front-matter absent/foreign = fine. | Body stays clean; `id` makes rename/move detection robust (DS-4) and travels with sync (Phase 2). **⚠ AMEND** DS-2 says "either/or"; propose "front-matter for user-meaningful fields, sidecar DB for derived/AI fields". |
| Derived DB (DS-3) | SQLite via **GRDB.swift** at `~/Library/Application Support/Filaway/<libraryKey>/filaway.sqlite`: notes, FTS5 (trigram + unicode61), chunks+embeddings, activity log, undo events, session baselines. Fully rebuildable (`Settings → Rebuild index`). | One file, transactional, fast FTS; GRDB is the mature Swift wrapper. |
| Keyword search | SQLite FTS5 over title+body (trigram for substring, unicode61 for word/prefix) + Levenshtein fuzzy on titles only. | <100 ms at 20k notes; offline. `[ASSUMPTION]` "fuzzy" = substring/prefix + typo-tolerant titles, not typo-tolerant body. |
| Semantic index | **Local embeddings** via Core ML: `bge-small-en-v1.5` (384-d) converted with coremltools and bundled (~35–65 MB), WordPiece tokenizer in Swift; chunks = heading sections + each fenced code block with its surrounding paragraph; vectors as BLOBs in SQLite + in-memory Float16 matrix, Accelerate cosine brute force; **hybrid** ranking = RRF(FTS5 BM25, vector) + temporal filter + recency prior; Claude (Haiku 4.5) reranks top-8 chunks and picks the answer snippet. | Anthropic has no embeddings API → must be local (also keeps index offline, FR-5.5). Core ML not MLX because Intel is in scope. **Contentious:** MiniLM-L6 vs bge-small — M3 benchmark decides; one-file swap behind `Embedder` protocol. Upgrade path `sqlite-vec` if 20k-note memory hurts. |
| AI provider | `AIProvider` protocol; `ClaudeProvider` = raw Messages API over `URLSession` (no official Swift SDK): strict tool-use JSON schemas for plans/answers, adaptive thinking with `effort: low/medium`, typed error taxonomy, backoff; `RecordingProvider`/`ReplayProvider` for tests; `MockProvider` for UI previews. Key in Keychain (`kSecClassGenericPassword`), validated via `GET /v1/models`. | NFR-5 abstraction; FR-6.4 degradation; replay fixtures make the whole pipeline testable offline. |
| Default models | Organization: `claude-sonnet-5` (default), `claude-opus-5` as Advanced override; search rerank/extraction: `claude-haiku-4-5`; model list fetched live from `/v1/models`. | User pays per token (FR-6.2 asks for cost/quality balance); Sonnet 5 is $3/$15 vs Opus 5 $5/$25, Haiku keeps search <5 s. **⚠ AMEND** Figure 4's `claude-sonnet-4-6` is stale; use current IDs. |
| Session/concurrency (FR-3.2) | Actor `SessionTracker` + actor `Organizer` with per-note serial queue. Each note has an *organized baseline* (content hash+text). Plan computed against note hashes; apply is **compare-and-swap** per note inside one transaction; CAS miss → whole plan discarded and note stays pending; user typing in a note cancels in-flight generation for that note and supersedes its pending plan. Apply never overwrites user text (append-only targets, segment moves). | Simplest semantics that guarantee "never lose text". Detailed in §4 M2-08. |
| File watching (DS-4) | Live FSEvents stream on root (file-level, 0.5 s latency) + full stat-scan on launch and on app activation; own writes tagged for echo suppression; moves detected by front-matter `id`; editor-dirty vs external-change → keep in-app buffer, preserve external version as `<Title> (external edit <timestamp>).md`, banner. | Live + scan covers both spec options; conflict rule loses nothing and honours "capture is sacred". |
| Autosave | Debounce 750 ms after last keystroke; flush on note switch, window resign key, app resign active, terminate, session end; atomic write (temp+rename). | Meets FR-2.3 ≤2 s window with margin; atomic write is crash-safe. |
| Updater | **Sparkle 2** via SPM, EdDSA-signed appcast hosted on GitHub Releases/Pages. | De-facto standard for non-MAS apps. |
| Signing / distribution | Developer ID Application cert, hardened runtime, no sandbox (spec §3), `notarytool` + staple, DMG via `create-dmg` script, GitHub Actions release job. | Required by Gatekeeper; proven end-to-end in M1, not M4 (risk #5). |
| Crash/diagnostics | No crash reporter in Phase 1; `OSLog` with privacy annotations; Help → "Export diagnostics" (zips logs, never note content). Opt-in reporter (e.g., Sentry w/ scrubbing) deferred. | NFR-4 zero-content telemetry; simplest compliant choice. |
| Prompts | Versioned text resources in Core (`organize.v1`, `answer.v1`), `promptVersion` recorded per activity event; golden replay tests per version; `filaway-bench prompts --live` re-records fixtures on change. | Spec §9 prompt-versioning; regressions caught by fixtures + retrieval benchmark. |
| Testing | Swift Testing for Core; XCTest UI tests (smoke + `XCTApplicationLaunchMetric`); `filaway-bench` CLI (corpus gen 5k/20k, keyword/semantic perf, retrieval benchmark); GitHub Actions `macos-15` runner; perf thresholds as failing tests. | Woven into milestones (§4). |
| Concurrency model | Swift 6 language mode in `FilawayCore` (actors: `NoteStore`, `Indexer`, `SessionTracker`, `Organizer`), Swift 5 mode + `-strict-concurrency=complete` warnings in the App target (AppKit interop). | Safety where logic lives; pragmatism at the AppKit boundary. |

### Conflicts / amendments flagged (⚠ AMEND)

1. **FR-4.4 vs FR-4.1 "merge"** — "never deletes content" vs merging a scratch note's code block into `Commands/curl`. Proposed: *merge = move segment* (target gets it appended under a divider; source segment removed in the same undoable event); a source note left empty is moved to the macOS **Trash** (recoverable) and its raw text kept in Activity for ≥30 days. Never a hard delete. Plan assumes this.
2. **FR-3.1 "switching away ends session immediately"** — the core user loop is *write command → ⌘-Tab to Terminal to test it → come back*. Immediate end means an API call + card every ⌘-Tab, then cancellation on return (FR-3.2). Proposed: deactivation/window-close *ends* the session but the pipeline starts after a **30 s grace**; resuming typing within the grace supersedes silently. `[ASSUMPTION]` grace is not user-visible in Settings.
3. **DS-2 either/or** → hybrid (see table).
4. **FR-6.1 "validate with a test call"** → `GET /v1/models` (free, validates key) instead of a billed message.
5. **Figure 4 model string** stale → current IDs, list fetched live.
6. **FR-5.1 "fuzzy"** → defined as above `[ASSUMPTION]`.
7. **FR-1.2 Recents "last-opened/last-edited"** → `max(lastOpened, mtime)` `[ASSUMPTION]`.
8. **FR-7.2 Apple Notes import** → deferred to Phase 1.x; `Importer` protocol + hidden menu stub ship in M4 (stated per spec).
9. **FR-2.5 attachments** → cut; storage accommodates later via `<root>/_assets/` + standard `![](…)` relative links (stated per spec).
10. **FR-4.7 Reorganize library** → cut from Phase 1 (COULD).

## 6. Running this with Opus sub-agents

- One milestone at a time; within a milestone, two agents in separate worktrees: **Track A (Core)** and **Track B (App/UI)**, then one integration agent for the `M*-last` task. Track B can start against Core protocols/stubs defined in the first Core task.
- Each agent prompt includes: this plan, the spec path, its task IDs + DoD rows, the conventions in §2.8, and “run `make test` (and `make bench` where the task says) before reporting; append decisions to `docs/decisions.md`”.
- Agents should be told the model IDs (`claude-sonnet-5`, `claude-haiku-4-5`, `claude-opus-5`) and that the API is raw HTTP Messages API with `output_config`/strict tools — no prefill, no `budget_tokens`.
- Human checkpoints (user): after M1-10 prototype (editor feel), after M2-10 (card UX), after M3-07 (benchmark numbers), before M4-05 release.

## 7. Verification (end-to-end)

1. `make setup && make test` — Core unit/replay tests + UI smoke green.
2. `make bench` — keyword p95 <100 ms @5k/20k; retrieval ≥90% top-1; index build timings printed.
3. `make app && open build/Filaway.app` — run the M-level DoD manual checklists (Fig 1–4 compared side-by-side with the spec HTML).
4. `make dmg && make notarize` — install on a clean macOS user; `spctl -a -vv` passes; Sparkle update test.
5. Dogfood a week; retrieval log ≥90% hits under 10 s.

## 8. Build-environment amendment (2026-08-22, discovered at kickoff)

The dev machine has **no Xcode.app** (Command Line Tools only, Swift 6.0.3, macOS 26.1) and **no code-signing identities**. Consequences, applied to all milestones:

- **Build = pure SwiftPM.** One root `Package.swift` with targets `FilawayCore` (library), `FilawayApp` (executable, SwiftUI/AppKit), `filaway-bench` (executable), `FilawayCoreTests`. No XcodeGen/`.xcodeproj` until Xcode is installed (then `project.yml` is additive).
- **App bundle = script.** `Tools/make_app.sh` assembles `build/Filaway.app` (Info.plist, binary, Resources) and ad-hoc signs (`codesign -s -`). `make run` launches it. DMG via `hdiutil`/`create-dmg`.
- **Signing/notarization/Sparkle EdDSA = blocked** on the user enrolling in the Apple Developer Program and installing Xcode. Tasks M1-02, M4-04, M4-05 are implemented as scripts that run end-to-end *up to* the signing step; notarization is verified once credentials exist.
- **UI automation:** XCTest UI tests need Xcode. Replace with (a) Core-level tests for all logic, (b) an AppleScript/`osascript` + `screencapture` smoke driver in `Tools/smoke.sh` for launch → ⌘N → type → relaunch, (c) manual DoD checklists.
- **Core ML:** `coremlcompiler` is Xcode-only → compile `.mlpackage` at first launch with `MLModel.compileModel(at:)` (cached) or via a tiny Swift script in `Tools/`. Embedder fallback ladder gains a zero-download option: `NLContextualEmbedding` (macOS 14+, mean-pooled) before `NLEmbedding`.
- **Action for the user:** install Xcode from the App Store and enrol in the Developer Program to unblock notarization, Sparkle signing, and XCTest UI tests.
